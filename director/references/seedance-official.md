## 1 · 官方推荐的写作结构

原文只说四段：

> 「把 Seedance 2.5 当作一个视觉内容生产者，用导演的思维书写 [结构化 Prompt]。」
>
> 1. **（R2V）素材指代** —— 明确每个图/视频/音频的编号（按上传顺序）与用途
> 2. **一句话概述** —— 主体 + 地点 + 事件 + 题材/风格 + 特殊运镜
> 3. **具体情节描述** —— 镜头顺序/时间轴（均可）：用时间戳或「镜头 N」切分，逐段描述画面内容、运镜、动作、台词、音效，**尽量使用正向描述**
> 4. **结尾** —— 补充贯穿始终的细节：机位/运镜、环境/场景、声音、氛围

但官方**模板**（正文案例）实际用八块，比四段更好落地：

```
【生成目标】    生成什么场景 + 风格 + 质感 + 环境细节
【主体与关系】  全程只有 N 人 + 各自位置关系 + 保持脸型年龄发型服装身高关系 + 恒定道具
【资产锁定】    角色A严格参考@[图片N]，角色B严格参考@[图片M]，场景严格参考@[图片K]
【事件脚本】    0—4 秒：……  4—9 秒：……  9—14 秒：……（每段结尾写"结束时……"）
【摄影与声音】  运镜风格 + 景深 + 表演质感 + <音效> + 音乐 + 无旁白无字幕
【保持一致】    身份/数量/外貌/服装/身高关系/空间方位/视线方向连续；关键道具；动作顺序；手部结构
【排除内容】    分类排除：卡通感 / 换脸 / 手部 / 声音 / 字幕
```

**本系统的 19 块可以映射到这 8 块**，映射见本文 §7。

## 2 · 时间戳：整数秒，连续，不许控频率

官方原文：

> 「时间戳可以更好地理清故事剧情发展，以「1 秒」为单位」
> 「指定时间段内剧情如果较少，模型会进行一定自由发挥」
> 「指定时间段内容过多，则会导致过度剪切或剧情遗漏」
> 「**不建议用时间戳控制频率/频次，比如「一秒摇头 3 次」**」
> 「明确的时间区间 [注意时间轴的连续性，**避免出现「0-3 秒...5-6 秒...」表达**]」

三种被支持的时间控制：

| 类型 | 官方示例 |
|---|---|
| 明确区间 | `0-3 秒......3-7 秒.....7-15 秒` |
| 时间点 | 「第 5s 快速向左横移转场」 |
| 相对时间 | 「张三呆滞的站在原地，3 秒后周围的人纷纷摇头」 |

**官方模板里的实际写法**：`0—4 秒` / `4—9 秒` / `9—14 秒` —— 全整数，首尾相接，无缺口。

### 还有一条藏在教程里的关键差异

> 「响应时间戳：**Seedance 2.0 不响应时间戳只响应镜头序号，而 Seedance 2.5 响应整数秒的时间戳。**」

**推论（本系统结论，非官方原话）**：写成 `0.0–2.5s`、`2.5–6.0s` 这种小数秒，2.5 可能不认。
**必须写成 `0—3 秒`、`3—7 秒`。**

## 3 · 正向为主，负向只管三件事

> 「逐段描述……尽量使用正向描述。」
> 「**反向描述支持：字幕、音频控制**，比如「不要字幕」、「不要 bgm」。」

但官方**模板里有【排除内容】块**，而且写得很具体：

> 「排除卡通感、滑稽恶搞、现代物品、掌掴、推搡和粗暴动作；排除人物换脸、年龄或服装变化、身高突变、角色增减、空间位置跳变和动作顺序混乱；排除手掌穿模、多余手指、手指粘连、手部畸形、脸部塌陷、五官扭曲、眼镜漂浮或消失；排除错误人物发声、多人同时说话、重复台词、漏词、口型错位和声画不同步；排除快速剪辑、跳帧、剧烈抖动、画面闪烁、字幕、文字、标志和水印。」

**结论（两条制度并存，不矛盾）**：
- **动作与画面内容** → 正向写（"他向后仰" 而不是 "他没有向前"）
- **已知失败项** → 集中在【排除内容】块，按类别列，一条一行，不散在各处
- **字幕与音频** → 允许直接负向（"不要字幕""无 bgm，只生成环境音和动作音"）

本系统原先把负向拆在 B18/B19 两处，**应合并成一块【排除内容】**。

## 4 · 素材绑定：先职责，再排除

官方原文：

> 「按照上传素材的顺序对应编号（图 1 / 视频 1 / 音频 1），每个素材进行文本绑定」
> 「**不建议只在图片里呈现映射信息**，比如主角图片上写「张三」，然后 Prompt 中直接写「张三在学校里 xxxx」，容易导致多人混淆或重复角色。」
> 「分工要具体到「参考什么」，如果是只分参考，要写明「参考哪一部分」。」
> 「**当参考素材本身已足够精准时，建议只做「指代」、减少画面复述。**」

官方给的示例写法：

```
@图片1用于[角色A]的五官、发型和服装，不采用图片背景。
@图片2用于[场所]的布局、材质和晨间光线，不采用图中人物。
@视频1用于[动作]的节奏，不采用视频中的人物身份、服装和场景。
```

**这条直接印证了本系统的 B02.5（先职责后 @ + 反向排除）。**
但要注意最后一条：**素材够准就只指代，别复述**——这一条本系统原先没写，容易写出"复述型长提示词"。

### 多视角图的写法（防"多出一个"）

```
@图片1定义同一盏台灯的正面外观。
@图片2定义同一盏台灯的左侧结构。
四张图片共同定义同一盏台灯，成片中始终只有一盏台灯。
```

## 5 · 素材上限与稳定区（官方表格）

| 项 | 官方建议 |
|---|---|
| 总上限 | **50 个参考素材** |
| 图片 | 最多 30 张，4K 分辨率以内 |
| 视频 | 最多 10 段，总时长 ≤30s |
| 音频 | 最多 10 段，总时长 ≤30s |
| 主体图数量 | **1–8 主体效果较好**；9–12 可试但稳定性下降 |
| 主体音视频 | 1–5 主体较好；每个 5–10s 较好 |
| 多视角主体图 | ≤5 主体时单/多视图均可；>5 主体用单视图，多视角拆成多张 |
| 宫格分镜 | **适用于 15 个以下分镜**；推荐火柴人/线稿；**不推荐在分镜图上写过多文字** |
| 白模参考 | **粗粒度**（简单几何体拼接）效果较好 |
| 视频编辑输入 | 20s 以内较好 |
| 视频延长格式 | 输入输出都用 mov，声画衔接最好 |

## 6 · 首尾帧的两种方式（差别在"锁不锁画幅"）

| 方式 | 效果 |
|---|---|
| 参数设 `role = first_frame / last_frame` | **锁定输出宽高比**，严格对齐首帧图 |
| 设 `role = reference_image`，在 prompt 里指定 | **不锁宽高比**，效果相近但不完全匹配 |

**另一个看不见的锁（来自第三方实测转述，非官方正文）**：
视频编辑任务的宽高比与时长被输入锁死（±0.3s）；首帧任务宽高比锁首帧图；视频延长锁输入画幅。
→ 结论：**要竖屏就直接生成竖屏，不要用 edit 把 16:9 转成 9:16。**

## 7 · 台词、音效、字幕

### 官方模板实际用的符号

| 内容 | 官方模板里的写法 |
|---|---|
| 台词 | `{像…… 太像了。终于等到你了，乡亲们有救了。}` |
| 音效 | `<烛火轻微燃烧声、衣料摩擦声和山神殿细微声响>` |
| 字幕 | 自然语言：「画面正下方显示粗体黑字"…"」 |
| 音乐 | 自然语言：「极轻的低沉弦乐铺底，不遮盖台词」 |

> 注：`( )` 音乐 / `【 】` 字幕 的说法来自 **Seedance 2.0** 指南（2.5 沿用），2.5 官方模板里改用自然语言。**两种都能用，但同一份提示词里不要混用两套符号。**

### 台词带情绪的写法（官方推荐，能压字幕）

```
周婆婆台词（难以置信）："像……"
周婆婆台词（声音发颤）："太像了。"
```

**为什么要这么写**——官方明确说：

> 「避免在台词后复述词语并追加语气、表情、动作等描述，**此类描述容易诱发字幕生成**。」
> 「提示词中已写明"不要字幕"，生成的视频仍可能出现字幕……目前无法完全避免，可降低概率。」
> 「确保参考视频本身不含字幕，否则"无字幕"指令可能失效。」

**推论**：台词单独成行 + 用"角色（情绪）：内容"格式，**不要在台词后面跟一句动作描写**。

### 语言规则

> 「所有配音台词都要用同一种语言，在同一个 prompt 里混用两种语言会出问题。」
> 「台词不是英语或中文时，要在台词前注明语言。」

公式：`语言 + 地区口音 + 表达方式 + 说话人 + {台词}`

## 8 · 其他官方明确支持的

- **景别/运镜/机位可以直接写**：大全景/全景/中景/近景/特写；推/拉/摇/移/跟/环绕/俯冲/后拉/上摇/手持晃动；低角度/俯视/第一人称
- **热门运镜可以直接写**：一镜到底、希区柯克变焦、航拍、FPV、子弹时间、手持、回弹变速
- **小众词要转成「名词 + 描述性解释」**：官方示例「移焦，画面焦点发生平滑转变，原本在前景清晰的树木变模糊，背景中的人物由模糊逐渐变得清晰。」
- **音频负向可细分**：`无 bgm，只生成环境音和动作音` / `不要任何声音`
- **官方模板里写"动作依次发生，不同时抢拍"** —— 这是抑制连招糊掉的有效表达

## 9 · 与本系统 19 块的映射

| 官方 8 块 | 本系统 19 块 | 差异 |
|---|---|---|
| 【生成目标】 | B01 场景上下文 + B15 风格 | 官方把风格并进目标，本系统单列 |
| 【主体与关系】 | B01 人数头 + B05 首帧站位 + B14 表演 | 官方把"关系"写进主体块 |
| 【资产锁定】 | B02 参考素材 + B02.5 绑定纪律 | **一致** |
| 【事件脚本】 | B03 GEO + B04 地理 + B06 模式 + B07 光学 + B08 摄影机 + B09 时间轴 | 官方**合并**成一个脚本块，本系统拆成 6 块 |
| 【摄影与声音】 | B10 物理 + B11 光照 + B12 声音 + B16 画质 | 官方合并 |
| 【保持一致】 | B17 几何锚点 + B18 正向约束 | **接近** |
| 【排除内容】 | B19 负向 | **本系统原先是散的，应合并** |

**结论：19 块没错，但交付时应该按官方 8 块排版。** 块的名字用官方的，粒度保留本系统的。

## 10 · 我实际踩到的三个坑（2026-10-20）

| 坑 | 我的写法 | 官方规则 | 后果 |
|---|---|---|---|
| 小数时间戳 | `0.0–2.5s`、`11.0–17.5s` | 2.5 只响应**整数秒** | 时间轴可能整段不被识别 |
| 时间戳控频率 | 「每 2 到 3 秒一次眨眼」「食指点两下，每下 0.15 秒」 | 「不建议用时间戳控制频率」 | 动作被机械均分 |
| 只写肌肉不写神情 | 「嘴角单侧向下压 2 毫米」 | 官方模板：**神情 + 身体反应 + 不做什么** 三者并写 | 表演僵硬，缺少整体方向 |

第三条要展开说：官方原文写「露出错愕不解的神情，身体下意识稍稍后仰，但不挣扎、不躲开」——**它用情绪词，但每个情绪词后面都跟一个可见的身体反应**。
本系统原先"绝不写情绪词"过于绝对，正确做法是：**情绪词只做整体定位，具体必须落到身体**。
