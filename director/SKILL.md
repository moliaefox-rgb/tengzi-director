# Seedance 导演系统

> 这套方法的每一层都从一部真实长片里长出来：Higgsfield Studio《Hell Grind》，95 分钟全 AI 制作，
> 2026 年 5 月 21 日戛纳首映，15 人 / 14 天 / 总成本不足 50 万美元，**全部提示词与素材开源**
> （`higgsfield.ai/@higgsfield.studio/projects/hell-grind`）。
> 下面的规则不是某人的偏好，是这个项目用 108,859 次生成换来的。

---

## 0 · 先认清三件事

**一、视频模型没有记忆。** 每次生成都是一张白纸。角色不在这一条提示词里被完整描述，下一镜就换脸换衣服。
一切技巧都是这一条事实的推论。

**二、一致性不是设置，是重复。** 描述词逐字进每一条提示词，永不缩写；风格前缀逐字粘贴；声音描述逐字复制。

**三、资产先行。** 在角色、场景、道具全部锁定并通过压力测试之前，**不要生成任何一个镜头**。
这一条省下的钱超过其他所有规则的总和。

---

## 0.5 · 暗号「地狱」

用户说 **「地狱」**——或「地狱」后面直接跟一段剧本 —— 就是调用本技能。

**收到之后的动作顺序（不要抢跑）：**

0. **先建归档文件夹**：用**剧本名**建 `剧本/<剧本名>/`（去掉书名号、不加日期），把 `剧本/_模板/` 的四份文件复制进去，并建 `prompts/`。
   同名文件夹已存在就**复用，不重建**。**这一步不用问用户，直接做。**
   **之后这个剧本的所有产出都只进这个文件夹**，一镜一个 `.txt` 放 `prompts/`。
1. **再确认四件事，不要先写提示词**：
   - register：真人电影 / 3D / 2D / 定格（不确定就从剧本语气里判断，并说出来让用户否掉）
   - **画幅：9:16 / 16:9 / 21:9**（决定走位语法，见 `references/blocking.md §10`；用户不说就问，别默认）
   - 项目：有没有现成的项目层 skill？没有就提议用 `templates/project-skill.md` 建一份
   - 资产：角色三视图 / 场景板 / 道具板锁了没有？**没锁就先做资产，不生成镜头**
2. **读剧本：先做场景研究，再拆。** 按 `references/scene-study.md` 三步走，不要跳：
   - **Scene Action**：这场「A 对 B 做了什么」，一句话，动词开头。
   - **Objective**：每个角色「他要——」，然后检查**两人是否对立**。一致 = 没戏，回去问用户。
   - **划 Unit**：谁的目标变了，就在那里切一刀。**Unit 数 = 镜头数**，不是按秒平分。
   定完 Unit 再写每场四行（发生什么 / 说了什么 / 每个 beat 几秒 / 几镜），四行必须对齐 Unit。
   划不出 Unit 就说明这场戏还没设计好，回去问用户，不要硬写。
   > 这一条是 2026-10-20 实拍补的。之前直接"拆事件"，结果镜头只能按时间切，
   > 六段十五个动作，成片丢十一个——因为**转折处没有划 Unit，模型不知道那是转折**。
3. **报一个清单给用户过目**：场次表 + 本场需要的资产 + 预估镜头数与迭代预算。
   用户点头，再进入逐镜组稿（B01–B19）。
4. **不要一次性输出几十条提示词。** 一场一场来，第一场先跑通，再复制它的结构。

> 一句话：说「地狱」不是让我马上写，是让我**接管这个片子的导演工作**。

## 0.7 · 语言：提示词用中文

**用户指定：交付给用户的提示词一律中文。** 方法论与解释也用中文。

三条硬规矩（细则与译名表见 `references/chinese-prompts.md`）：
1. **块名固定**：场景上下文 / 参考素材 / 空间平面图 / 场景地理 / 首帧与空间锁 / 镜头模式 / 光学 / 摄影机 / 动作时间轴 / 物理 / 光照 / 声音 / 台词 / 角色表演 / 风格 / 画质 / 几何锚点 / 正向约束 / 负向约束。
2. **术语一个词只有一个译法**，永不换说法（`画左/画右`、`上三分之一`、`180 度轴线`）。
3. **防文学腔**：短句、动词、每句至少含一个数字或一个物理事实。台词只出现在「台词」块，加引号。

不译的：人名、@tag、`47°`、模型名、摄影师/导演名。

## 0.8 · 边界：这个系统不碰什么

它只负责**「从剧本到提示词」这一段**。以下区域**只读，不写、不搬、不改**：

| 区域 | 规矩 |
|---|---|
| `~/.workbuddy/skills/` 下**任何其他技能** | 只按名调用。**不改文件、不复制内容、不搬进本系统** |
| 特别是**编剧类**：`short-drama-craft`、`screenplay-studio`、`sw-*`（四十个）、`drama-*`、`story-five-elements`、`script-evaluator`、`chekhov-dramaturgy`、`ozu-screenplay-style`、`qiangzhi-short-script` | **那套是用户自己的资产，一个字节都不动。** 需要判断时"请它判断"，结果写进场景卡；**技能本身不参与改写** |
| 用户的剧本原稿 | 只读。改稿属于编剧技能的职责，不属于本系统 |
| 项目以外的文件 | 不碰 |

**为什么写这一条**：整合期最容易犯的错，是把别人的技能"吸收"进来，结果原技能被改、被复制、
版本分叉，最后两套说法互相矛盾。**引用 ≠ 复刻。** 需要调用就调，需要沉淀就写自己的话，
但原文件永远不动。

> 这一条对我是硬约束：**编辑范围只限 `导演系统-整合版/` 与桌面产出**。
> 动别人的技能目录之前，必须先问，得到明确同意才动手。

## 1 · 路由：这句话该走哪条路

| 用户说什么 | 先读 | 产出 |
|---|---|---|
| 写一条镜头提示词 / 这场戏怎么拍 | `references/blocks.md` | 19 块骨架填满的成品 |

| 表演不对、眼神死、反应假、像在念台词、两个人不在同一场戏里 | `references/acting.md` | 表演段重写（含"一个方向不同燃料"与 FACS 面部码） |

| 给一条已经失败的提示词做诊断 | `references/failure-modes.md` | 故障定位 + 单点修复 |
| 审这一场 / 这算不算过了 / 帮我挑毛病 | `references/review.md` | 逐镜 PASS/FAIL 判定 + 必改清单 |
| 这场戏的镜头为什么这么摆 / 这一帧怎么构图 / 色彩怎么定 | `references/composition.md` | 关系压力 + 视线流量 + 色彩命题 |
| 这条规则哪来的 / 能不能信 / 怎么记这次的实验结果 | `references/evidence-log.md` | 规则入库卡 + 生成记录 + 对照实验表 |
| 参数怎么写 / 时间戳格式 / 台词怎么标 / 素材上限 | `references/seedance-official.md` | 官方原文条款 + 本系统踩过的坑 |
| 准备交付 / 帮我检查一遍 / 这条能不能发 | `references/preflight.md` | 24 项可数检查 + 5 条一票否决 |
| 上一条为什么崩 / 有没有真实案例 | `references/postmortem.md` | 实拍复盘（带秒数、帧号、根因） |

**一次只加载需要的那个 reference。** 不要一次把五个都读进来——那不是系统，是噪音。

> **三个新层，用在高频处：**
> 写之前看 `composition.md`（这一帧为什么值得看），写完落 `review.md`（逐格判 PASS/FAIL），
> 出片后记 `evidence-log.md`（这条规则到底成立不成立）。
> **三者顺序不能反** —— 用构图层去审成片，等于用菜谱尝菜。

## 1.5 · 证据门槛（写规则之前）

**这套系统里的每一条规则，都要能指回一个做过片的项目。** 指不回去的，不写进来。

### 四道门槛（全中才算数）

| 门槛 | 具体要求 | 不合格的样子 |
|---|---|---|
| **真实项目** | 能追溯到成片 / 作品 / 客户案例 / 可复现的产出记录 | "我测过，很好用" |
| **星数与使用** | 优先 300★ 以上；看 issue、PR 里有没有人在真用 | 星高但 issues 全是求教程 |
| **无商业引流** | README 不导流付费站、不带 utm、不是提示词汇集堆叠 | 首页一个"立即购买" |
| **能上生产** | 有 license、近半年有提交、写了失败模式与边界 | 只有 10 张好看的效果图 |

### 检索顺序（不许跳步）

```
GitHub 搜索 → 看仓库树（不是只看 README）→ 读 references/ 里的方法文件
→ 至少两个独立来源交叉 → 标来源等级 → 才写进规则
```

### 反面清单

名字很专业但**不能用**的：提示词汇集（`awesome-xxx-prompts`）、商业站引流仓库、
无 license 的仓库、半年以上停更的、只讲美学不讲失败的、二手转述来源不明的。

### 找不到证据时

1. 在回复里**明说"这一点没有可核验依据"**
2. 标 `[UNTESTED]`，列为**待验证假设**
3. **不许写进铁律、不许进模板**——模板一旦写错，后面每一条镜头都错
4. 可以给建议，但要说明这是建议不是说结论

### 已采信的一手与二手来源

| 来源 | 等级 | 用途 |
|---|---|---|
| Higgsfield Studio《Hell Grind》（95 分钟长片全开源） | A · 一手 | 19 块骨架、资产法、表演法、迭代纪律 |
| OSideMedia/higgsfield-ai-prompt-skill（767★ MIT） | A · 可溯源 | 2.5 参数面、GEO、失败库、证据标签制度 |
| nutllwhy/seedance-tvc-director（321★ MIT） | B · 生产实践 | 生成段数 vs 有效镜头、节奏密度档 |
| lukasersil/seedance-25（MIT） | B · 规格核对 | 30 秒窗口结构、End state、官方时长边界 |

**落地台账在 `references/evidence-log.md`** —— 规则入库卡怎么填、生成记录记哪些字段（含 sha256）、
要做对照实验时用什么表、哪些查证动作有效而哪些会骗你。**光有门槛没有台账，三个月后你会忘了某条规则从哪来。**

**一句话自查**：这条规则，我能指回一次具体生成、或一个能打开看的仓库吗？
指不回去 → 标 `[UNTESTED]`，不许进模板。

## 2 · 十二条铁律

1. **资产先行。** 角色/场景/道具没锁死，不生成镜头。
2. **每次都说全。** 描述词逐字进每条提示词，不缩写、不同义改写。
3. **一次只改一处。** 提示词是一台工作着的机器，重写等于丢掉已经奏效的部分。
4. **给模型更少的自由。** 一个角落而不是一整间房；一个锚点而不是一片空地；一张地图而不是靠猜；每镜一个动作。
5. **镜头出不来，简化镜头，不是简化文字。** 拆成两镜、删一个动作、换角度。
6. **只写正面。** 模型会忽略 `does NOT fall`，或者干脆照做。要写 `falls on his stomach`。
7. **不写年龄。** 任何语言都不写。内容过滤器一读到未成年就收紧。用角色身份、衣着、动作替代。
8. **只留环境音。** `SFX only. No music.` 是强制的——音乐属于后期，生成的配乐只会在剪辑台上碍事。
9. **镜头 = 一个动作改变。** 一场戏有几次"关系或信息的位置变化"，就几个镜头。
   30 秒塞 6 段 15 个动作，实测只完成 4 个，丢的全是转折（见 `postmortem.md 案例 001`）。
   **宁可少拍一个过程，不可少拍一个转折。**
10. **每段动作 ≤2 个**（≤3 只能用于因果成对的动作：捏→松、推→倒）。
   超过 3 个，模型按运动预算挑最省力的实现，其余全丢，而每一帧看起来都合理。
11. **抽象动词必须拆三件套**：哪块身体 / 往哪个方向 / 停在哪。
   "搂住"会说成"靠近"，"捏脸"会变成"掐下巴"，"嗅"会变成"啃"。
12. **一条规则只在一个地方生效。** 正面说了 X，别处不许再禁 X。
   规则打架时模型随机挑一个执行——这是最难查的一类崩，因为提示词"看起来都对"。

## 3 · 证据标签：每条规则都要知道它有多硬

写在引用规则时一并标注，防止把偏好当规律。

| 标签 | 含义 |
|---|---|
| `[FIELD]` | 真实制作中验证过（Hell Grind / ANERNEQ） |
| `[CRAFT]` | 传统手艺（表演学、剪辑学），无生成实测 |
| `[OFFICIAL]` | 厂商文档或平台参数 |
| `[UNTESTED]` | 经验法则，待回归验证 |
| `[EXPIRED]` | 条款已过期（如"15 秒上限"） |

## 4 · 十九块骨架

**顺序固定。缺块可以，改序不行。** 详细写法与逐块范例见 `references/blocks.md`。

| # | 块 | 写什么 | 最常见错误 |
|---|---|---|---|
| B01 | **SCENE CONTEXT** | 首行 `EXACT N CHARACTERS — NO DUPLICATES: A, B, C.` 然后一两句：发生什么、谁在、几条几秒 | 漏掉人数头 → 模型加人 |
| B02 | **ACTIVE REFERENCES** | 每个素材一行：`@tag for character reference — 状态` / `@loc for location reference — 只取空间与材质，不继承构图、角度、调色` | 只写 tag 不写角色 → 模型自己决定，一定决定错 |
| B03 | **GEO SPATIAL LAYOUT** | 场景级纯空间地图：地标、左右、机位在哪侧、180° 轴线。**不含人、不含动作**，同场景每镜原样粘贴 | 把人和动作写进来 → 每镜都不一致 |
| B04 | **LOCATION MAP** | 本镜的地理：前景/中景/背景、距离（米）、光从哪来 | 用 "near / around / somewhere" |
| B05 | **FIRST FRAME AND SPATIAL BLOCKING** | 首帧就已经是全部人到位；每人屏幕位置、世界位置、朝向、视线 | 留空镜或延迟露人 |
| B06 | **FORMAT MODE** | 单镜连续 / 受控多镜；时长；实时；无变速 | 用了多镜却不写切点 |
| B07 | **OPTICS** | 视角**度数**（8/18/29/47/84/107°）+ 机距 + 想要的视觉结果 | 写 `85mm f/1.4` 当主要控制 |
| B08 | **CAMERA** | 高度、机位侧、手持的物理质感；以及镜头**永远不做什么** | 复合运镜（推+摇+移）堆在一个 beat |
| B09 | **ACTION TIMING** | `0—3 秒 — …` **整数秒**，每段 **≤2 个动作（按动词数）**，结尾写"结束时……" | 一段塞 3 个以上动作 → 只完成一个 |
| B10 | **PHYSICS** | 质量、接触、惯性、布料/头发延迟、液体黏度、道具重量 | 用形容词代替物理（"沉重地"） |
| B11 | **LIGHTING** | **一个光源逻辑**：主光、方向、比值、哪里允许全黑；**脸的受光侧要有细节** | 两个太阳；写成剪影 |
| B12 | **AUDIO** | 只写同期声；点名谁说话、说什么、别人不出声 | 把台词写进动作段 |
| B13 | **SPOKEN LINE** | 每个说话角色的 voice 描述**逐字** + 引号内台词，一句不多；**台词后不跟动作** | 改一个词 → 声音漂；跟动作 → 出字幕 |
| B14 | **CHARACTER ACTING** | 每人：**整体神情 + 一个可见身体反应 + 不做什么** | 只写心理（会乱演）/ 只写毫米级（会僵） |
| B15 | **STYLE** | Style Prefix **逐字粘贴**（见 §6） | 每镜重新发明风格词 |
| B16 | **QUALITY** | 细节与稳定性：8K 细节、毛孔级皮肤、不抖不闪、脸在任何景别都是参考里的人 | 用 8K 当质量保证（它只是设置） |
| B17 | **GEOMETRY ANCHOR** | 数字：角度、距离、高度 | 用"靠近"代替米数 |
| B18 | **POSITIVE CONSTRAINTS** | 每个"数量"和"禁令"都写成**画面里有什么**：`画面里恰好两个人` | 写成一串 `no xxx` |
| B19 | **【排除内容】** | **集中一块**：字幕 / 音频 / 真实失败项，按类别分号分隔 | 散在各处、抄通用负词表 |

**长度**：成品提示词可以很长——**制作里是 3,000–4,000 词**。长不是敌人，**过载的 beat 才是**。

> **19 块是思考框架，不是你交付的格式。**
> 交付时压成官方 8 块，用 `templates/prompt-8blocks.md` 填空。
> 19 个标题原样贴给模型，它读的是标题不是内容。

## 5 · 三种 register：开项目第一件事

你的片子是真人电影感；3D / 2D 是另外两套语法。**登记错，全片全错。**

| Register | 摄影机语法 | 质感栈 | 风格锚点写什么 |
|---|---|---|---|
| **真人电影** | 手持呼吸、允许地平线不平 | 35mm 颗粒、门织、光晕、低对比 | 摄影师的**光与镜** |
| **3D 动画** | 稳定、可编排、可穿墙，镜头是设计过的 | 次表面散射、毛发解算、真实接触阴影、**无胶片颗粒** | 渲染器的**材质与光比** |
| **2D 动画** | 每镜一个具名机位，物理描述大幅减少 | 赛璐璐平涂、2–3 阶色阶、线条粗细、手绘背景 | 美术**年代/画风** |
| **定格** | `animated on twos`，姿势停两帧再跳 | 手作痕迹、微缩景深 | 介质的**物理** |

三个 register 的完整前缀与词库：`references/style-library.md`。

**画幅也是语法，不只是参数。** 三种画幅是三套走位：

| | **9:16** | **16:9** | **21:9** |
|---|---|---|---|
| 双人 | 对角叠，上压下承 | 可并排，中间留对话空间 | 横向拉开，中间留空气 |
| 前景 | **必须有** | 建议有 | 用环境做（门框/柱/树） |
| 人 vs 环境 | 人占满 | 五五 | **人变小**，地理是主角 |
| 运动 | 禁横摇，推/降/升 | 横移、轨道、升降 | 横向跟移、缓推，**慢** |
| 最容易犯的错 | 把横屏裁一刀 | 拍成没观点的中性图 | 人太小，情绪读不到 |

完整对照（含选型判断、竖屏五种双人排法、宽银幕细则、多画幅项目怎么改）见 `references/blocking.md §10`。

## 7 · 出稿前检查

**只做一件事：过 `references/preflight.md` 的 24 项 + 5 条一票否决。**
那里每一项都能数出来，这一节不重复列——**两套清单等于没有清单**。

交付时在文件头写凭证：`检查：★1✓…E4✓`。有一项不 ✓ 不许交，不许写"基本通过"。

### 三个最容易自己骗自己的地方

| 自欺 | 实际 |
|---|---|
| "这段写了五个动作，但都是连贯的" | 连贯不等于模型能做完。**五个动作它只做一个。** |
| "我写了'不握紧'" | 如果你别处又写"五指扣住"，那就是两个指令，模型随机选。 |
| "时间戳我写了 2.5 秒，它应该懂" | 2.5 **只认整数秒**。`0.0–2.5s` 可能整段不被识别。 |

## 8 · 失败图谱：症状 → 修法

> 这里是速查。**完整失败库（10 条，含实测数据与出处）见 `references/failure-modes.md`。**

| 症状 | 真因 | 修法 |
|---|---|---|
| 人物换脸 / 换衣服 | 描述词被缩写，或参考素材没写角色 | 描述词逐字补全；素材加"角色 + 排除" |
| 多了一个人 / 家具复制 | 没有人数头，或点数没写 | `EXACT N` 头；把数量写进 POSITIVE CONSTRAINTS |
| 人物瞬移、左右互换 | 没有 GEO，或每镜重写了地图 | GEO 写一次，逐镜原样粘；每个切点后重述谁在哪、看哪 |
| 机位跑到反侧 | 没写 180° 轴线 | `camera ALWAYS stays on the X side — it NEVER crosses the line` |
| 动作糊成一团 | 一个 beat 塞了多个动作 | 一 beat 一动作；复杂动作**放在开头**（"already mid-swing"） |
| 眼神死 | 只写了"看着" | 分阶段眨眼（懒眨 → 双眨 → 硬重启）+ 明确视线方向 + 每秒一个微事件 |
| 脸像蜡 / 塑料 | 图像过了两次模型 | 点改动只用蒙版贴回原图，**原图不整张二次过模型** |
| 画面像游戏 / CGI | 风格前缀缺失，或分辨率词当质量词 | 逐字粘 Style Prefix；加 `NON-IP, NO CGI` |
| 口型不对 / 多出台词 | 台词写进了动作段 | 台词只在 AUDIO；加"只有引号内的话，其他人完全不出声" |
| 声音每镜都变 | voice 描述被改写 | voice 描述逐字复制，一个字都不改 |
| 巨物变小 | 没有尺度锚 | 尺度法则：画面里放人 + 身体地标（"只到脚踝"）+ 写出什么叫失败 |
| 光照每镜不同 | 场景没有单一光逻辑 | 一个光源一个方向；把光写进 location 资产 |

## 9 · 工作流

```
0 读本    Scene Action → 每个角色的 Objective（对立吗）→ 划 Unit（目标一变一刀）
          **Unit 数 = 镜头数**，不按秒平分。见 scene-study.md
1 资产    角色三视图（正面无头 + 背面 + 特写）、场景 3/4 板、道具板 → 压力测试 10/10
2 地图    GEO 写一次（纯空间）
3 表演    每个 Unit 内：共同方向 → 每角色 goal/obstacle/tactic → 一个可见证据
4 组稿    8 块模板填空（19 块只在脑子里用）
5 生成    480p Draft 验构图 → 成立再出 1080p
6 修      单点走 Edit；续写走 Extend；只改一行
7 归档    版本、改了什么、结论 全部进日志
8 检查    preflight 24 项 + 5 条否决，写凭证
```

**三个数不许混**：成片时长 / **生成段数**（调几次模型）/ **有效镜头数**（成片里几个镜头）。
一条 30 秒可以装 **8–18 个有效镜头**，且默认**单段生成**（2.5 原生 30 秒）。
「16 镜 + 1 段 30 秒」是合法组合；只有平台不支持、或局部控制收益大于连续性损失时才拆段。详见 `references/blocks.md` B06。

**迭代纪律**：同一镜**10–15 次**还不出，问题不在措辞。拆镜头、删动作、换角度。
真实基准（Hell Grind）：图片验收率 ≈1%、视频 ≈1.5%，主角锚点 ≈800 次，一个 10 秒过场镜跑过 72 次。
