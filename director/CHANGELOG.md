### 三条不可动摇的纪律

1. **`[UNTESTED]` 不进模板。** 模板错一次，后面每条镜头都错。
2. **`[REF-xx]` 不许在交付物里说成"行业标准"。** 它是一套设计得不错的机制，不是被验证过的规律。
3. **原技能 `~/.workbuddy/skills/seedance-director/` 未被修改。** 这一版在工作区里，随时可对照回滚。

### 这一版最该被质疑的地方

`review.md` / `evidence-log.md` / `composition.md` 的主要来源里，**没有一个做过客户交付的公开证据**：

- 61 是私域包，无公开仓库
- 69 是 1 次提交、0 issue
- 45 的作者自己在 README 里否认"性能保证"

它们的方法论自洽、可执行，但**没被第三方验证过**。所以全部标 `[REF-*]` / `[CRAFT-*]`，不标 `[FIELD]`。
真正的 `[FIELD]` 只有一条线：**Hell Grind 那部 95 分钟长片**。

**你要做的事**：用三个项目把里面的规则跑一遍，能跑通的升 `[FIELD]`，跑不通的标 `[EXPIRED]`。
在那之前，它是好用的假设，不是结论。

## v2 修订（2026-10-20 深夜，实拍驱动）

一次 30 秒真实生成（《猫系男友》第四集，480×854，721 帧）暴露了六类问题。
完整取证见 `references/postmortem.md 案例 001`。**这次修订全部来自那条片子，不是推测。**

### 改了什么

| 改动 | 原状 | 现状 |
|---|---|---|
| **铁律 8 条 → 12 条** | 没有"动作预算"概念 | 新增 9–12：镜头=一个动作改变 / 每段 ≤2 动作 / 抽象动词三件套 / 一条规则只在一处生效 |
| **12 问 → preflight 24 项** | 12 问是"有没有写"，判不出来 | 24 项全部**可数**，附 5 条一票否决，交付要写凭证 |
| **B14 表演** | "状态/想要/在藏什么"+"不许出现情绪词" | 改成**神情 + 身体反应 + 不做什么**（官方范式，两个极端都试过） |
| **B19 负向** | 局部负向、"默认省略" | 合并成**【排除内容】**块，只处理字幕/音频/真实失败项 |
| **B09 时间块** | "≤1 个动作"（按句子） | **≤2 个动作（按动词数）**，并给出怎么数 |
| **新增 8 块模板** | 19 块直接当交付格式 | 19 块只做思考框架，交付用 `templates/prompt-8blocks.md` |

### 新增文件

- `references/preflight.md` —— 24 项 + 5 条否决，**这是本系统真正的刹车**
- `references/postmortem.md` —— 实拍复盘库，唯一带成片证据的部分
- `templates/prompt-8blocks.md` —— 固定 8 块填空，减少自由发挥

### 这次修的是"幻觉"

不是模型的幻觉，是**我的幻觉**。四种：

1. **以为写了就等于会执行**（写了五个动作，以为会拍五个）
2. **以为转折不说也在**（删掉"她要起身"，以为模型会自己补）
3. **以为抽象词能落地**（"搂住""嗅"直接写，以为模型懂）
4. **以为规则越多越稳**（其实规则打架时，模型随机挑一个）

对应四道闸：**动作数上限 / A3 镜头=改变数 / B4 三件套 / E4 矛盾检查**。

### 一句话

**这份系统现在的价值，不在它写了多少方法，在它能在出稿前拦住多少已知的错。**
`preflight.md` 里 13 条病史，每一条都是真的崩过一次。

## v3：补上「读剧本」这一层（2026-10-20 深夜）

### 缺的到底是什么

不是编剧知识。你机器里已经有四十多个编剧技能：`short-drama-craft`（钩子/爽点/节奏波形）、
`screenplay-studio`（732 部校园剧统计）、`sw-*` 四十个、`drama-analyzer`、`script-evaluator`……

**缺的是「导演读本」这一层。** 上面那些全是**编剧视角与评估视角**：
故事好不好、爽点够不够、结构对不对。它们不回答导演要问的那个问题——
**这场戏该怎么切成镜头。**

所以之前只能按"时间"切，切成六段十五个动作。

### 找到了什么

GitHub 上这一层**没有合格件**（`scene-study` / `shotlist` / `screenplay-analysis` /
`script-breakdown` 四组搜下来最高 56★，且都是"剧本格式统计"或"提示词生成"，不是导演判断）。

真正的来源在导演工作法里，两份**互相独立、结论一致**：

| 来源 | 给了什么 |
|---|---|
| Mackendrick《On Film-making》 | **一场戏 = 一个明确的目的与意图**，内部含更小的 steps；先写 step outline（因果链，不是场景清单） |
| Weston《Directing Actors》 | **Scene Action → 每个角色的 Scene Objective → 拆 Unit Action；objective 一变就换 unit** |

### 结论（这条改变了整个流程）

> **镜头不是按时间切的，是按「谁的目标变了」切的。**
> **Unit = 镜头。**

案例 001 的四个 unit 正好是四个镜头：
她逼他吐 → 她改口确认 → 她要走 → 他留住。
我按时间切成了六段，每段内目标变了两三次，模型每次只有一个执行额度 → 丢十一个动作。

### 新增

- `references/scene-study.md` —— 三步读本、场景卡模板（含「可删清单」）、Activity vs Action、
  从 Unit 到镜头的三条硬规则。
- §0.5 接单流程第 2 步改写：**读剧本先做场景研究，再拆事件。**

### 分工（不重复造轮子）

```
short-drama-craft（已有）  判钩子、爽点、节奏波形、集尾留扣 —— 只做判断
        ↓
scene-study（新）          转成导演视角：Scene Action / Objective / Unit / 镜头数
        ↓
acting.md（已有）          每个 unit 内的目标、障碍、战术、身体
        ↓
8 块模板 → preflight 24 项
```

### 证据等级

`[CRAFT]`。两位导演的工作法高度一致，但**没有生成实验数据**。
唯一支持它的是案例 001 的反向验证：按时间切必崩。
在你的项目里跑三条，能稳定降崩，再升 `[FIELD]`。
